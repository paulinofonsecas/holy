# Data Model: Firebase APK Distribution

**Feature**: 012-firebase-apk-distribution  
**Phase**: Phase 1 - Design & Contracts  
**Date**: 2026-01-04

## Overview

This document defines the data structures and configuration models for Firebase APK distribution automation. Since this is infrastructure tooling, the "data model" primarily consists of script configuration parameters, environment variables, and file system artifacts.

---

## 1. Distribution Configuration

### Entity: DistributionConfig

Represents the configuration required to execute Firebase App Distribution upload.

**Attributes**:

| Attribute | Type | Required | Default | Description |
|-----------|------|----------|---------|-------------|
| `apkPath` | String (FilePath) | No | `build/app/outputs/flutter-apk/app-release.apk` | Absolute or relative path to APK file |
| `appId` | String | Yes | Auto-detected from firebase.json | Firebase app ID (format: `1:xxx:android:xxx`) |
| `releaseNotes` | String | No | `""` | Release notes text or file path (prefix with `@` for file) |
| `groups` | String (CSV) | No | `"internal-testers"` | Comma-separated tester group aliases |
| `testers` | String (CSV) | No | `""` | Alternative: comma-separated email addresses |
| `firebaseToken` | String (Secret) | No (CI only) | `$env:FIREBASE_TOKEN` | CI authentication token (not used locally) |
| `dryRun` | Boolean | No | `false` | Preview actions without executing upload |
| `debug` | Boolean | No | `false` | Enable verbose Firebase CLI output |

**Relationships**:
- References `firebase.json` for app ID extraction
- References APK file artifact from Flutter build process
- Consumed by distribution scripts (PowerShell/Bash)

**Validation Rules**:
- `appId` must match pattern: `\d+:\d+:android:[a-f0-9]+`
- `apkPath` file must exist and have `.apk` extension
- `apkPath` file size must be > 0 bytes
- If `firebaseToken` not provided, user must be authenticated via `firebase login`
- `groups` or `testers` can be specified, but not both simultaneously
- `releaseNotes` if starting with `@`, must reference existing file

**State Transitions**:
N/A (stateless configuration - each distribution is independent)

## 2. Build Artifact

### Entity: ApkArtifact

Represents the APK file generated by Flutter build process.

**Attributes**:

| Attribute | Type | Required | Description |
|-----------|------|----------|-------------|
| `filePath` | String (FilePath) | Yes | Absolute path to APK file |
| `fileName` | String | Yes | File name (e.g., `app-release.apk`) |
| `fileSize` | Integer (bytes) | Yes | Size of APK file in bytes |
| `buildVariant` | String | Yes | Build variant (`release`, `debug`, `profile`) |
| `versionCode` | String | No | App version code (extracted from APK metadata if needed) |
| `versionName` | String | No | App version name (extracted from APK metadata if needed) |
| `modifiedTime` | DateTime | Yes | Last modified timestamp of APK file |

**Relationships**:
- Generated by `flutter build apk` command
- Consumed by DistributionConfig as `apkPath`
- Uploaded to Firebase App Distribution service

**Validation Rules**:
- File must exist at specified path
- File extension must be `.apk`
- File size must be > 0 and < 1GB (Firebase limit)
- `modifiedTime` should be recent (within 24 hours) for automated distributions

## 3. Firebase Project Configuration

### Entity: FirebaseProject

Represents Firebase project configuration extracted from project files.

**Attributes**:

| Attribute | Type | Required | Source | Description |
|-----------|------|----------|--------|-------------|
| `projectId` | String | Yes | firebase.json | Firebase project ID (e.g., `admin-we-barato`) |
| `androidAppId` | String | Yes | firebase.json | Android app ID for App Distribution |
| `webAppId` | String | No | firebase.json | Web app ID (not used for APK distribution) |
| `windowsAppId` | String | No | firebase.json | Windows app ID (not used for APK distribution) |

**JSON Structure** (from firebase.json):
```json
{
  "flutter": {
    "dart": {
      "lib/firebase_options.dart": {
        "projectId": "admin-we-barato",
        "configurations": {
          "android": "1:86790721181:android:19238f375ace9f62db0e74",
          "web": "1:86790721181:web:1ac47f755219c4d9db0e74",
          "windows": "1:86790721181:web:8a683fe1c409f183db0e74"
        }
      }
    }
  }
}
```

**Relationships**:
- Single source of truth for Firebase app IDs
- Read by distribution scripts for automatic app ID resolution
- No write operations (configuration is static)

## 4. Script Execution Context

### Entity: ExecutionContext

Represents the runtime environment for script execution.

**Attributes**:

| Attribute | Type | Description |
|-----------|------|-------------|
| `platform` | Enum | Operating system (`Windows`, `Linux`, `macOS`) |
| `shell` | Enum | Shell environment (`PowerShell`, `Bash`) |
| `isCI` | Boolean | Whether executing in CI/CD environment |
| `workingDirectory` | String (Path) | Current working directory (repository root) |
| `firebaseCliVersion` | String | Installed Firebase CLI version |
| `firebaseAuthenticated` | Boolean | Whether user is authenticated with Firebase |
| `environment` | Map<String, String> | Environment variables (includes `FIREBASE_TOKEN` if CI) |

**State Determination**:
```text
isCI = (env:CI == "true" OR env:GITHUB_ACTIONS == "true")
firebaseAuthenticated = (firebase login status == authenticated)
firebaseCliVersion = (firebase --version output)
```

**Validation Rules**:
- Firebase CLI must be installed (`firebaseCliVersion` not null)
- If `isCI == true`, `FIREBASE_TOKEN` environment variable must be set
- If `isCI == false`, `firebaseAuthenticated` must be `true`
- `workingDirectory` must contain `firebase.json` file

## 5. Distribution Result

### Entity: DistributionResult

Represents the outcome of a distribution attempt.

**Attributes**:

| Attribute | Type | Description |
|-----------|------|-------------|
| `success` | Boolean | Whether distribution succeeded |
| `exitCode` | Integer | Script exit code (0 = success, non-zero = failure) |
| `apkPath` | String | Path to APK that was distributed |
| `appId` | String | Firebase app ID used |
| `groups` | String | Tester groups targeted |
| `uploadDurationSeconds` | Integer | Time taken for upload (if successful) |
| `errorMessage` | String | Error details (if failed) |
| `retryAttempts` | Integer | Number of retry attempts made |
| `firebaseReleaseId` | String | Firebase release ID (if successful, extracted from output) |
| `timestamp` | DateTime | Execution timestamp |

**Logging Format**:
```text
[2026-01-04 14:30:00] Distribution Result:
  Success: true
  APK: build/app/outputs/flutter-apk/app-release.apk
  App ID: 1:86790721181:android:19238f375ace9f62db0e74
  Groups: internal-testers
  Duration: 45 seconds
  Release ID: abc123xyz
```

**State Transitions**:
```text
Initial → InProgress → (Success | Failure)
  ↓ (if network error)
  Retrying → (Success | Failure | Retrying)
```

## 6. Tester Group Configuration

### Entity: TesterGroup

Represents a Firebase App Distribution tester group (configured in Firebase console).

**Attributes**:

| Attribute | Type | Description |
|-----------|------|-------------|
| `alias` | String | Group alias used in commands (e.g., `internal-testers`) |
| `displayName` | String | Human-readable name in Firebase console |
| `memberCount` | Integer | Number of testers in group |
| `description` | String | Group description/purpose |

**Note**: Tester groups are **managed in Firebase Console**, not by these scripts. Scripts only reference groups by alias.

**Common Group Aliases**:
- `internal-testers`: Internal development team
- `qa-testers`: QA and testing team
- `beta-testers`: External beta testers
- `stakeholders`: Product owners and stakeholders

## 7. Script Parameters Model

### PowerShell Script Parameters

**distribute-apk.ps1**:
```powershell
param(
    [Parameter(Mandatory=$false)]
    [string]$ApkPath = "",
    
    [Parameter(Mandatory=$false)]
    [string]$AppId = "",
    
    [Parameter(Mandatory=$false)]
    [string]$ReleaseNotes = "",
    
    [Parameter(Mandatory=$false)]
    [string]$Groups = "internal-testers",
    
    [Parameter(Mandatory=$false)]
    [switch]$DryRun,
    
    [Parameter(Mandatory=$false)]
    [switch]$Debug
)
```

**build-and-distribute.ps1**:
```powershell
param(
    [Parameter(Mandatory=$false)]
    [string]$ReleaseNotes = "",
    
    [Parameter(Mandatory=$false)]
    [string]$Groups = "internal-testers",
    
    [Parameter(Mandatory=$false)]
    [switch]$SkipTests,
    
    [Parameter(Mandatory=$false)]
    [switch]$DryRun
)
```

### Bash Script Parameters

**distribute-apk.sh**:
```bash
APK_PATH="${1:-}"          # First positional argument
APP_ID="${2:-}"            # Second positional argument
RELEASE_NOTES="${3:-}"     # Third positional argument
GROUPS="${4:-internal-testers}"  # Fourth argument with default
DRY_RUN="${DRY_RUN:-false}"      # Environment variable
DEBUG="${DEBUG:-false}"          # Environment variable
```

**build-and-distribute.sh**:
```bash
RELEASE_NOTES="${1:-}"
GROUPS="${2:-internal-testers}"
SKIP_TESTS="${SKIP_TESTS:-false}"
DRY_RUN="${DRY_RUN:-false}"
```

## 8. Environment Variables

### CI/CD Environment Variables (GitHub Actions)

| Variable | Type | Source | Description |
|----------|------|--------|-------------|
| `FIREBASE_TOKEN` | Secret | GitHub Secrets | Firebase CI authentication token |
| `FIREBASE_APP_ID` | Secret | GitHub Secrets | Firebase Android app ID |
| `CI` | Boolean | GitHub Actions | Always `true` in CI environment |
| `GITHUB_ACTIONS` | Boolean | GitHub Actions | Always `true` in GitHub Actions |
| `GITHUB_REF_NAME` | String | GitHub Actions | Branch or tag name |
| `GITHUB_SHA` | String | GitHub Actions | Commit SHA |
| `GITHUB_WORKSPACE` | Path | GitHub Actions | Repository workspace path |

### Local Development Variables (Optional)

| Variable | Type | Description |
|----------|------|-------------|
| `FIREBASE_APP_ID_OVERRIDE` | String | Override app ID from firebase.json (for testing) |
| `DEFAULT_TESTER_GROUP` | String | Override default tester group |

## Configuration Precedence

When determining configuration values, scripts follow this precedence (highest to lowest):

1. **Command-line arguments** (explicit user input)
2. **Environment variables** (CI/CD context)
3. **firebase.json** (project configuration)
4. **Default values** (built into scripts)

**Example for App ID**:
```text
1. --app parameter (explicit)
2. FIREBASE_APP_ID env variable (CI secret)
3. Extract from firebase.json
4. ERROR if none found (no default for app ID)
```

## Summary

This data model covers all configuration and runtime data structures for Firebase APK distribution:

- ✅ **DistributionConfig**: Script input parameters
- ✅ **ApkArtifact**: Build output to be distributed
- ✅ **FirebaseProject**: Project configuration from firebase.json
- ✅ **ExecutionContext**: Runtime environment detection
- ✅ **DistributionResult**: Execution outcome and logging
- ✅ **TesterGroup**: Firebase console-managed groups
- ✅ **Script Parameters**: PowerShell and Bash interfaces
- ✅ **Environment Variables**: CI/CD and local configuration
